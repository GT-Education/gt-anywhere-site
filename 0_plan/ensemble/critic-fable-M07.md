## Ruling on the disagreement (my fix 6, the day card's school name)

**The engineer is right and I withdraw the fix.** Three reasons, each measured.

First, the defect I actually objected to was proximity, not repetition: at iteration 0 the day card's "Georgetown Campus" sat **41px** under an identical door card. It no longer does. Measured at V11, the door name runs 392.1–416.9 and the day-card name 618.4–643.1 — **201.5px apart**, with the 44px CTA and the card's top hairline between them; at V3 the gap is 203.2px. The restructure fixed the thing I was pointing at.

Second, my own fix 3 required each week row to be named where it starts, on the grounds that a picture identified only by adjacency is not self-identifying. The day card **is** that week row at card scale — the same two bands, the same five columns, the same caption. Stripping its name at 768 would have reinstated at card scale the precise defect I insisted be fixed at grid scale, and the two cards would then be told apart only by column order.

Third, my own iteration-0 compliance row already accepted the name on the phone, "where the door has scrolled away". Dropping it only at 768 would make a school's name appear and disappear by breakpoint — a conditional identity, which is worse than a repeat 200px down the page.

And what the engineer dropped instead is the right thing to drop: the day card's "In person" / "Online" eyebrow (`.day .label` count now 0). The door card two hundred pixels above already carries that label, and the card is a picture of a day, not a second door. The substitution is a better fix than the one I asked for.

**Verdict: Pass — all nine rows at or above 4** (Objective 5, Composition 4, Typography 5, Imagery 5, Colour and surface 4, Motion 5, Mission and exclusivity 5, Craft 4, Continuity 4), with the brief's expected 5s on Objective and Mission both met; the four remaining fixes are polish and none blocks the gate.
