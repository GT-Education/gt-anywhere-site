## The seven rulings asked for

**1. The two orange GT icons, against K3 section 5f's one accent use per screen. The engineer's reading is upheld, and on stronger ground than the engineer gave it.** The argument offered — that 5f counts the accent spent as a design device, not the pigment inside an unmodified brand file — is right, but it is stated as a preference. It is not a preference; it is the only reading under which the rule can be obeyed at all. `gt-school-logo-h.svg` is **five accent-orange paths and one navy** (`grep fill`), and CONTRACT.md section 1 fixes that file, checker R16 requires it in the header and the footer, and `copy.md` section 8 forbids recoloured marks. So the header lockup puts accent orange on **every screen of every mock in the programme** before any designer draws anything. Reading 5f to count brand pigment would make every screen non-compliant by construction and would set the rule in direct conflict with two other fixed rules. A rule cannot be read so that compliance is impossible. The icons stay, and they earn their place independently: the same mark on both doors is the thesis stated in ink — one school, two ways in — and it is the only thing tying two differently tinted cards back to the lockup above them. One consequence worth recording rather than fixing: in forced colours the tint is gone and the two identical icons carry no distinguishing information (`forced-colors.jpg`), so the doors are told apart there by label and name alone, which is sufficient and is what DD-04's cue set intends.

**2. The application pair carries no tint. Upheld, and again the governing reason is not the one given.** The rationale argues from the copy — both schools get the same four steps, so the band is shared ground. True, but it proves too little; the two buttons go to different schools and carry different `school=` parameters. The reason that actually settles it is the page's own key, which I checked across the whole document: **no control on this page is ever tinted.** The door CTAs are navy on tinted cards; the repeated doors under the two tinted columns are navy on cream; the TEFA link is a text link on a tinted surface, not a tinted control; the footer links are plain (`V14-full.jpg`). Tint is a property of surfaces here, never of actions. Tinting the application pair would make it the single tinted control on the page and would contradict the key at the exact moment a parent acts on it.
