# 1_spec: the build specification

| Field | Value |
|---|---|
| What this is | The buildable contract derived from `0_plan/`. Every requirement, decision and fact in the plan lands in one of these documents with tasks (T ids), verification checks (V ids), and acceptance criteria that a model or a person can observe |
| Reading order | `00` scope and traceability, `10` build and operations, then the doc for the surface you are working on, then `11` verification |
| Rule | If the spec and `0_plan/` disagree, fix `0_plan/` first. The spec never invents a fact: unknowns appear as `TBD (Q-nnn)` |
| Integrity | `python3 0_plan/tools/check-links.py`, `python3 1_spec/tools/check-paths.py`, `python3 1_spec/tools/check-coverage.py`, `python3 1_spec/tools/check-runlog.py`, then `python3 0_plan/tools/build-index.py` and `python3 1_spec/tools/build-traceability.py`. All six before every commit and every gate |
| Status | v0.1, 2026-09-10. Awaiting Johnny's review; nothing built |
